# Supermemory для DeepSeek Harness

Долговременная память для агента [DeepSeek Harness](https://github.com/deepseek-ai) (DSH) на сервере
[Supermemory](https://supermemory.ai) (API v5): собственный namespace для записи, опциональное чтение
памяти других агентов (например, Гермеса), автоматический recall перед ходом и автоматическое
сохранение завершённой сессии.

- **Своя память.** Всё, что агент сохраняет и захватывает, идёт в свой namespace (`dsh` по умолчанию).
- **Чужое — только по явному разрешению.** Namespace другого агента подключается как read-only, каждый
  факт помечается контейнером и подаётся как недоверенный фон.
- **Recall перед ходом.** Последний вопрос ищется до первого шага, найденные факты вставляются в блоке
  с одноразовым маркером (nonce) на каждый ход.
- **Capture после хода.** Сессия перезаписывается как один документ (`dsh-<sessionId>`) или, если не
  влезает, как части `dsh-<sessionId>-p1…pN`; части обновляются на месте. У документа есть настоящая
  дата (начало сессии, для части — её самый ранний ход) и группа контекста, поэтому «когда я это
  сказал» не теряется даже при поздней или возобновлённой записи.
- **Полный путь чтения v5.** `supermemory_search` отдаёт `include.related`, `include.documents`,
  `include.forgotten`, `rerank`, `threshold` и типизированный `filter`; результаты несут дату и
  состояние `superseded` / `inferred` / `forgotten`, а не только текст.
- **История памяти.** `supermemory_memory_history` читает одну память по id: цепочку версий,
  связи `extends`/`derives`, даты и при желании фрагмент исходного документа — то есть эволюцию
  позиции, а не только её последнюю формулировку.
- **Двенадцать инструментов**: search, memory_history, profile, save, save_many, forget, read_document,
  list, namespaces, upload_file, namespace, buckets.
- **Встроенный skill.** Бандл регистрирует skill `supermemory` (как официальный skill Supermemory):
  когда искать, что стоит сохранять, как читать историю памяти и как индексировать проект; модель
  загружает его по необходимости, а не держит инструкции в каждом промпте.
- **Recall не повторяется.** Факты, уже показанные в сессии, пропускаются, профиль обновляется по
  расписанию, а не подмешивается каждый ход, поиск предпочитает извлечённые памяти с более высоким
  порогом, и блок говорит, откуда факты.
- **Честный recall.** Если recall не успел, блок прямо говорит об этом
  (`memory recall unavailable (timeout) — proceed without memory`), а не отдаёт молча только профиль.

## Что нужно

| Компонент | Требование |
|---|---|
| DSH | `@deepseek-ai/dsh` `0.2.2-rc.1` или новее (`engines.dsh: >=0.2.2-0`). |
| Сервер Supermemory | Свой локальный **или** облачный. |
| Ключ API | В хранилище credentials DSH под ссылкой `SUPERMEMORY_API_KEY`. |
| Node | 22+ для интерактивного `scripts/setup.mjs`. |

### Сначала выберите сервер

| Вариант | Запуск | Ключ |
|---|---|---|
| Локальный (приватнее) | один раз `npx supermemory local install`, затем `npx supermemory local start` | `cat ~/.supermemory/api-key` |
| Облачный | ничего запускать не нужно | создать в консоли Supermemory |

Локальный сервер по умолчанию слушает `127.0.0.1:6767` (`PORT` или `--port` меняют порт; в старых
релизах было `8787`). Скрипт настройки пробует оба порта и находит запущенный сервер.

Скрипт настройки сам проверяет локальный сервер, спрашивает вариант и печатает готовую строку конфига:

```bash
node scripts/setup.mjs                 # интерактивно, нужен терминал
node scripts/setup.mjs --mode local    # или --mode cloud, без вопросов
node scripts/setup.mjs --json          # машинный план (код 3 и needDecision в stderr, если сервера нет и --mode не задан)
```

Облако не выбирается молча: без локального сервера скрипт спросит (или вернёт `needDecision`). При
облачном сервере транскрипты сессий уезжают с машины.

## Установка

В **DSH Desktop** команды `dsh` в оболочке нет — плагин ставится через сам DSH. Выберите один путь:

1. **Попросить агента** (работает сразу): сказать ему установить бандл

   ```
   plugin_manager install_bundle → git+https://github.com/eagurin/dsh-supermemory.git#v0.9.1
   ```

2. **GUI**: *Plugins → Add plugin* — вставьте
   `git+https://github.com/eagurin/dsh-supermemory.git#v0.9.1` в поле **Package name or address**.

3. **CLI**, если есть Node 22+ и сеть (профиль `desktop` должен уже существовать, приложение — быть
   полностью закрыто, `pnpm` — быть в `PATH`):

   ```bash
   npx @deepseek-ai/dsh plugin --profile desktop add "git+https://github.com/eagurin/dsh-supermemory.git#v0.9.1"
   ```

Бандл сам вставляет свой `cordis.patch.yml`, вручную строку писать не нужно. Обычный
`pnpm add` внутри профиля ставит пакет, но **не** добавляет его в `dsh.profile.bundles`, поэтому плагин
останется неактивным — используйте один из трёх путей выше.

<details>
<summary>Вставка строки вручную (продвинутое)</summary>

`- id: supermemory` — это **оверрайд**: он заменяет конфиг существующей записи, а на чистом профиле DSH
пропускает его с предупреждением `patch: entry "supermemory" not found` (профиль при этом поднимается). Чтобы добавить плагин без выбора бандла, оберните строку в
`insert`:

```yaml
- insert:
    - id: supermemory
      name: '@local/dsh-supermemory'
      config:
        baseUrl: http://127.0.0.1:6767
```
</details>

## Настройка

Ключ API в конфигурацию и в репозиторий не попадает — только имя ссылки. Значение кладётся в
хранилище credentials DSH, которое перечитывается на лету:

```yaml
# $DSH_HOME/.credentials.yaml  (по умолчанию ~/.dsh/.credentials.yaml)
version: 1
refs:
  SUPERMEMORY_API_KEY: <ваш ключ>
```

Затем `chmod 600 "$DSH_HOME/.credentials.yaml"`: DSH отказывается читать хранилище, доступное другим
пользователям, и сообщает, что ключ пуст. Как запасной источник работает переменная окружения
`SUPERMEMORY_API_KEY`, выставленная до запуска DSH, но приложение, запущенное из Finder, её не наследует.

Все настройки необязательны; оверрайд заменяет `config` бандла, а пропущенные ключи берут значения по
умолчанию (полная таблица — в [README.md](README.md#configure)):

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `baseUrl` | `http://127.0.0.1:6767` | Адрес сервера (порт локального по умолчанию; в старых релизах было `8787`). |
| `container` | `dsh` | Свой namespace — единственный, куда идёт запись по умолчанию. |
| `readContainers` / `readPrefixes` | `[]` | Чужие namespace для чтения. **По умолчанию пусто** (opt-in). |
| `allowWritesToReadContainers` | `false` | Разрешить запись в читаемые namespace (кроме гермесовых). |
| `autoRecall` / `autoCapture` | `true` | Автоматические recall и capture. |
| `maxCaptureChars` | `120000` | Предел тела транскрипта; больше — режется на части (к документу добавляется короткий заголовок). |
| `captureTurnsPerChunk` | `25` | Ходов в одной части (минимум 1). |
| `filter` | `""` | Фильтр по метаданным (JSON) для recall в своём namespace. |
| `recallMaxResults` | `5` | Фактов в автоматическом recall-блоке. |
| `recallSearchMode` | `memories` | Поверхность поиска для recall (извлечённые памяти без дублей чанков). |
| `recallThreshold` | `0.5` | Порог релевантности для recall (у инструмента поиска остаётся `threshold`). |
| `recallFactMaxChars` | `320` | Максимальная длина факта в recall-блоке. |
| `recallQueryMaxChars` | `500` | Максимальная длина запроса recall. |
| `recallQueryCacheMs` | `600000` | Переиспользовать успешный одинаковый recall-поиск между сессиями; `0` выключает. |
| `recallScope` | `all` | `project` — recall только по `project_id` или имени этого репозитория (заметка, сохранённая без контекста проекта, под scope не попадает). |
| `recallDedupe` | `true` | Пропускать факты, уже показанные в этой сессии (сбрасывается после компакции). |
| `discoveryNotice` | `true` | Один раз сказать сессии, что recall ничего не нашёл и стоит вызвать поиск. |
| `captureTools` | `true` | Включать в захват вызовы инструментов и их результаты (с именами и ошибками). |
| `captureToolChars` | `800` | Максимальная длина текста результата инструмента в захвате. |
| `captureFailureNotice` | `true` | Сообщать в следующем recall-блоке о неудачном захвате. |
| `searchRetry` | `true` | Один повтор пустого `supermemory_search` с rewrite и более широким режимом. |
| `profileSectionFacts` | `8` | Фактов в секции профиля до пометки `+N more`. |
| `recallIncludeRelated` | `false` | Показывать в recall-блоке связи (`updates`/`extends`/`derives`); по одной связи на факт. |
| `recallRerank` | `inherit` | Reranking для recall-поиска; `inherit` берёт значение `rerank`. |
| `recallFailureNotice` | `true` | Явная строка `memory recall unavailable (…)` в блоке, если recall упал или не успел. |
| `dreaming` | `instant` | Режим обработки явных сохранений и загрузок файлов (`instant` или `dynamic`). |
| `captureDreaming` | `dynamic` | Режим обработки автоматического capture; `inherit` берёт значение `dreaming`. `dynamic` группирует связанные захваты (лучше памяти, позже видны), `instant` — сразу и с доп. операцией на документ. |
| `captureContext` | `""` | Подсказка извлечения для capture (≤1500 символов); пусто — решает сервер. |
| `rewriteQuery` | `false` | Сервер переформулирует запрос (+~400 мс). |
| `allowFileUpload` / `uploadRoots` | `false` / `[]` | Загрузка локальных файлов и разрешённые каталоги. |
| `maxUploadBytes` | `20971520` | Предел размера файла. |
| `redactSecrets` | `true` | Вырезать похожие на ключи строки из захвата. |
| `captureRetries` / `captureRetryDelayMs` | `3` / `4000` | Повторы захвата и базовая задержка (умножается на номер попытки). |

### Что можно спросить

- **«Что я говорил/решал про X?»** — `supermemory_search` по теме, затем
  `supermemory_memory_history` по id факта, если важна прежняя формулировка.
- **«Как менялась моя позиция?»** — `supermemory_search` с `includeRelated: true` показывает
  `updates`/`extends`/`derives` с датами; заменённые и забытые версии видны с `includeForgotten: true`
  и пометками `superseded`/`forgotten`.
- **«Какие решения приняты и когда?»** — сохраняйте решения с `date` и
  `group: {project, kind: "decision"}` и фильтруйте по ним
  (`{"field":"kind","operator":"eq","value":"decision"}`), а не надейтесь на ранжирование.
- **«Что мы делали в этом проекте?»** — `supermemory_list` по документам с `sort: "updatedAt"` или
  поиск с фильтром по группе проекта.

В личном namespace изначально есть только bucket `preferences`. Если хотите раздельно хранить
решения, состояние проектов и жёсткие ограничения, добавьте buckets один раз (бандл сам серверное
состояние не меняет):

```text
supermemory_buckets → action: set, buckets: {"decisions": "Решения владельца и их даты",
                                            "projects": "Активные проекты и их состояние",
                                            "constraints": "Жёсткие ограничения и non-goals"}
```

### Чтение памяти Гермеса

Чтение памяти других агентов намеренно выключено. Чтобы подмешивать память Гермеса (только чтение), добавьте
оверрайд:

```yaml
- id: supermemory
  name: '@local/dsh-supermemory'
  config:
    readContainers: [hermes_default]
    readPrefixes: [hermes]
```

## Модель безопасности

Гарантируется:

- **Секретов нет** в репозитории, логах, ошибках и выводе инструментов; ключ резолвится на каждый запрос.
  Тело ошибки сервера не передаётся вовсе: ошибка называет endpoint, HTTP-статус и стабильный машинный
  код, а для типовых статусов — фиксированную подсказку. Поэтому endpoint, который эхом вернёт ключ или
  напишет инструкции, не попадёт ими в контекст модели.
- **Запись только в свои namespace.** `writeContainers` не может назвать namespace Гермеса, а
  `allowWritesToReadContainers` на гермесовы не распространяется. Удаление namespace — по allowlist:
  только тот, куда агент вправе писать, никогда свой, и `moveTo` больше нет.
- **Recall нельзя подделать.** Блок ограничен одноразовым nonce на каждый ход; из подмешиваемого текста
  убираются управляющие символы, устаревший тег `<supermemory-context>` и заголовки `##`.
- **Из захвата и записи вычищаются секреты.** Формы ключей (`sm_…`, `sk-…`, `ghp_…`, `AKIA…`, `Bearer …`, PEM-блоки,
  `"apiKey": "…"`) заменяются на `[redacted]` до отправки.
- **Capture удаляет только свои документы.** Перед удалением legacy-документа сессии плагин
  перечитывает его и требует собственные `session_id` и метаданные агента, поэтому заметка с
  совпавшим id не будет удалена.
- **Текст документа подаётся как недоверенный.** `supermemory_read_document` очищает заголовок, а
  сам (точный) текст оборачивает в собственный nonce-блок с предупреждением.
- **Загрузка файлов выключена** по умолчанию и ограничена `uploadRoots`; файл открывается с
  `O_NOFOLLOW`, обязан иметь одну жёсткую ссылку и читается через дескриптор с ограничением размера.
- **Необратимое — в два шага.** `supermemory_forget` сначала показывает совпадения и удаляет только с
  `confirm: "delete"`; удаление namespace — так же.

Не гарантируется:

- Сервер видит то, что вы захватываете: вопросы при recall и транскрипт при capture. С облачным
  сервером эти данные покидают машину.
- Изоляция namespace обеспечивается плагином, а не сервером: API сервера общий на аккаунт.
- Шифрование данных на диске — ответственность сервера.

Как сообщить об уязвимости — [SECURITY.md](SECURITY.md).

## Проверка

```bash
node --check index.js && node --check scripts/setup.mjs
node scripts/check.mjs
npm test              # 209 случаев; 6 live-случаев пропускаются без временного namespace
```

Живая проверка после установки: `supermemory_namespaces` показывает сервер и ваш namespace;
`supermemory_search` находит сохранённое; после хода в namespace появляется документ. Если данных
Гермеса ещё нет, поиск про Гермеса законно вернёт пусто.

Опциональный live-набор пишет только во временный namespace `dsh-audit-<YYYYMMDD-HHMM>`, читает
реальную память из своего `dsh`, чтобы проверить историю, и в конце удаляет временный namespace:

```bash
DSH_SM_LIVE_CONTAINER=dsh-audit-20260101-1200 \
SUPERMEMORY_API_KEY="$(cat ~/.supermemory/api-key)" \
node --test test/live.test.mjs
```

Любое другое имя namespace отклоняется, как и namespace, существовавший до запуска. Если на self-hosted сервере недоступна модель извлечения
(в логе `memory agent failed`), документы сохраняются и ищутся как чанки, но новые памяти не
появляются — зависящие от извлечения проверки честно сообщают об этом, а не «проходят».

## Архитектура и ограничения

- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — recall, capture, части, фильтры, buckets, namespace.
- [docs/API-COVERAGE.md](docs/API-COVERAGE.md) — какие пути и параметры v5 используются, какие
  осознанно нет, и где каждый пункт проверяется тестом.
- [CHANGELOG.md](CHANGELOG.md) — история релизов, включая несовместимые изменения.
- Capture читает список сообщений сессии: после компакции транскрипт отражает сжатый вид, поэтому
  содержимое частей может перезаписываться (id при этом стабильны).
- Recall выполняется только на первом шаге хода и ограничен бюджетом (`recallMaxChars`,
  `recallTimeoutMs`); неудачный recall виден в блоке, а не молчит.
- Обработка документов асинхронная: сохранённый документ становится доступен для поиска после
  обработки. Памяти (и версии) появляются на второй фазе — «dreaming»: `instant` отдаёт их сразу
  после обработки и стоит одну дополнительную операцию на документ, `dynamic` группирует связанные
  документы и может занимать минуты. Для этой фазы self-hosted серверу нужна рабочая модель
  извлечения; без неё документы сохраняются и ищутся как чанки.
