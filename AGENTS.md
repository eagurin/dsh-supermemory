# AGENTS.md

Правила для агента (DSH, Hermes, Codex — любого), который меняет этот репозиторий.

## Что это

Плагин-бандл DSH: долговременная память на официальном Supermemory API v5.
Один namespace для записи, чужие namespace — только на чтение. Плагин не переносит
данные между namespace; серверное состояние он меняет только явными инструментами
`supermemory_namespace` (`supportingContext`, удаление) и `supermemory_buckets`;
документы он читает и пишет через публичный API.

## Перед установкой

- **Спроси оператора, где жить памяти:** свой локальный сервер (`npx supermemory local install` один раз, затем
  `npx supermemory local start`; ключ в `~/.supermemory/api-key`) или Supermemory Cloud (транскрипты уезжают).
  Не выбирай молча — это решение оператора.
- Для этого есть `node scripts/setup.mjs`: он пробует локальный сервер, спрашивает, если его нет, и печатает
  готовую строку Loader'а. `--json` даёт машинный план, `--mode local|cloud` — ответ без вопросов.
- Установка — `plugin_manager install_bundle` с `git+https://github.com/eagurin/dsh-supermemory.git#vX.Y.Z`
  (в DSH Desktop нет команды `dsh`) либо GUI **Plugins → Add plugin** (вставить spec в поле **Package name or address**); бандл сам вставляет свою
  строку. Строка `- id: supermemory` — это оверрайд, она не устанавливает плагин на чистом профиле; для ручной
  установки нужен `insert`.
- Оверрайд заменяет `config` бандла, а пропущенные ключи берут значения по умолчанию. Не рассчитывай, что
  «все ключи обязательны»: обязательных нет, но и не теряй осознанно заданные значения.

## Границы

- **Гермес — другой агент.** В `hermes_*` писать нельзя; `allowWritesToReadContainers`
  не включать. Факты Гермеса нельзя выдавать за действия DSH.
- **Секреты.** В репозиторий попадают только имена credential-ссылок
  (`SUPERMEMORY_API_KEY`) и `${credential:…}` в конфигурации. Значения ключей,
  `~/.dsh/.credentials.yaml`, `api-key` локального сервера — никогда, ни в файлы,
  ни в чат, ни в коммит.
- **Официальный API.** Только задокументированные маршруты v5, например `/ns`,
  `/ns/{ns}/search`, `/ns/{ns}/document`, `/ns/{ns}/document/file`,
  `/ns/{ns}/memories`, `/ns/{ns}/memories/semantic`, `/ns/{ns}/list/{type}`,
  `/ns/{ns}/profile`, `/ns/{ns}/profile/buckets`. При сомнении — документация
  Supermemory, не догадки.
- **Зависимостей почти нет.** Runtime — только `node:` builtin'ы, плюс одна
  объявленная зависимость `@deepseek-ai/schemastery` (схема конфига), в дереве
  которой нет install-скриптов. Новую зависимость добавлять только с причиной в
  `CHANGELOG.md`.

## Не ослаблять защиту

Эти свойства — часть контракта, а не деталь реализации. Меняя код, сохраняй их:

- блок recall ограничен одноразовым nonce на ход; из подмешиваемого текста вычищаются управляющие символы,
  устаревший тег `<supermemory-context>`, поддельные `<<<supermemory-…>>>` и заголовки `##` (`sanitizeUntrusted`);
- захват проходит через `redactSecrets` до отправки;
- запись — только в свои namespace: `writeContainers` не может назвать гермесов, удаление namespace — allowlist
  без `moveTo`;
- необратимые операции требуют `confirm: "delete"`, forget сначала показывает совпадения;
- загрузка файлов — только `allowFileUpload` + `uploadRoots`, открытие с `O_NOFOLLOW`, одна жёсткая ссылка,
  чтение через дескриптор с лимитом;
- инструменты регистрируются через `defineTool`, чтобы модель получала настоящую JSON Schema.

Тест, который «зелёный» при сломанной защите, хуже отсутствующего: для каждого пункта выше есть тест — если
поведение меняется, меняется и тест, и это видно в diff.

## Процесс

1. Правка кода — здесь; в `dsh-build` остаётся только ссылка, пин и причина.
2. Перед коммитом: `node --check index.js && node scripts/check.mjs` — код
   возврата обязан быть 0.
3. `CHANGELOG.md` обновляется в том же коммите, что и код; версия в
   `package.json` — semver, тег релиза `vX.Y.Z`.
4. Проверка живой памяти (сервер поднят, ключ есть в credential store):
   `supermemory_namespaces` → `supermemory_search` с запросом про Гермеса
   (результаты помечены `hermes_default`) → `supermemory_save` тестового
   документа в свой namespace.
5. Не менять `package.json.name`: имя `@local/dsh-supermemory` закреплено в живом
   профиле и в записи `dsh-build`.
6. Версия в `package.json` и тег `vX.Y.Z` совпадают, и ссылка на установку в README указывает на эту версию:
   `scripts/check.mjs` падает, если это не так.

## Чего здесь нет

- кода других плагинов и сборки профиля (`dsh-build`);
- сессий, чатов, вложений и локальных путей машины как части контракта;
- значений секретов и конфигов чужих namespace.
